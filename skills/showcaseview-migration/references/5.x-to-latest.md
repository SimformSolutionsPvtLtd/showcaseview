# showcaseview: 5.0.x → latest (5.1.0)

No compile errors in this range. The changes below affect behavior, or add
the tools to handle the 5.0.0 behavior change.

## From < 5.1.0

### A forward step with no mounted target now ends the tour

If the next key in the list has no `Showcase` in the widget tree (a widget in
another tab, behind a condition, or in a lazy list item that is not built),
moving forward now finishes the tour at once: `onFinish` and the finish
listeners run. Earlier versions did not end the tour in this case. Stepping
backward to a missing target does not finish the tour.

Decide per tour what the app wants:

```dart
// Skip missing steps silently and continue with the next one.
_showcaseView = ShowcaseView.register(skipIfTargetNotPresent: true);

// Or only include steps that are on screen.
final steps = [
  _tabKey,
  if (_showcaseView.isTargetRendered(_bannerKey)) _bannerKey,
];
_showcaseView.startShowCase(steps);
```

### `isTargetRendered(key)`

`ShowcaseView.isTargetRendered(key)` returns `true` while a `Showcase` with
that key is mounted in the view's scope. It replaces the pre-5.0.0 check
`key.currentContext != null` (see `4.x-to-5.0.0.md`, "The key is no longer
attached"). It reports mounted, not visible on screen.

### Rapid taps and unmount

Barrier taps during a step's exit animation are ignored, and a tour dismissed
or unregistered while a step is changing no longer crashes. No app change is
needed; remove workarounds that guarded against these.

## From < 5.0.2

### `skipIfTargetNotPresent`

`ShowcaseView.register(skipIfTargetNotPresent: true)` skips steps whose
`Showcase` is not mounted (default `false`).

### New options and listeners

- `ShowcaseView.register` accepts `overlayColor`, `overlayOpacity` and
  `semanticEnable`. A `ShowcaseView` `overlayColor` / `overlayOpacity` wins
  over the values on each `Showcase`, so setting them changes every tour in
  that scope.
- `addOnStartCallback` / `removeOnStartCallback` and `addOnCompleteCallback` /
  `removeOnCompleteCallback` join the finish and dismiss listeners.
- `Showcase(onTargetRectUpdate: (rect) {...})` reports the target's rect each
  time it is recalculated.
- `Showcase(scope: 'name')` assigns a step to a named scope explicitly instead
  of the scope that was active when it was first built. Use it wherever more
  than one scope exists (a `Showcase` built after a named `register` and
  without `scope:` joins that named scope).

## Check

Run each tour once. If a tour has steps that may be missing, confirm it ends
or skips as intended. If any screen registers a named scope, confirm its
`Showcase` widgets carry the same `scope:`.
